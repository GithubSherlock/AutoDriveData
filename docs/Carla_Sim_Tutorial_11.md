# Carla仿真系列：12_激光雷达+语义分割，构建仿真环境的点云地图

前11期做的都是"让车看得懂"——检测、分割、测距、融合，一套感知链路走完了。但自动驾驶还有另一条关键主线：车得知道自己在哪、周围长什么样。这期做建图：用激光雷达+前视相机+GPS，在仿真环境里构建一张点云地图——而且不是裸点云，是带语义标签的，能分清路面、车、灯杆。

## 1 建图原理

建图程序用 C++ 实现，核心就一句话：让每个激光点都知道"自己是什么、在世界坐标系的哪里"。

激光雷达（点云） ──┐

前视相机（语义分割）─┼──→ C++建图程序 ──→ 世界坐标系点云地图 ──→ RViz

GPS（坐标）───────┘

内部流程：

每帧点云 → 点云投影到相机图像 → 每个点拿到语义标签

              ↓
              
        转换到GPS坐标系 → 累积成点云地图

激光雷达提供精确的3D位置，相机语义分割负责"认东西"，GPS负责"对齐到世界坐标"——三路数据一融合，就是一张会"分类"的3D地图。

## 2 启动流程

### 2.1 环境准备

整套流程 5 个终端，跟系列前面的操作一脉相承。

1. 启动容器

```bash
cd carla_sim
bash dev_start.sh
```

2. 进入镜像

```bash
bash dev_into.sh
```

3. 启动 Carla UE4

```bash
cd /opt/carla_ws
bash ./CarlaUe4.sh
```

4. 启动 ROS Bridge

新开一个终端：

```bash
cd carla_sim
bash ros_bridge.sh
```

5. 启动建图程序

新开一个终端：

```bash
cd /opt/carla_ws/sim_workspace/pointcloud_map/build
pointcloud_map 0 1
```

两个参数，决定了建什么样的图：

| 参数 | 取值 | 含义 |
| --- | --- | --- |
| 参数 1（模式） | 0 | 纯激光点云的地图 |
|  | 1 | 激光点云 + 语义分割的地图 |
|  | 2 | 激光点云 + 道路、地面、灯杆的地图 |
| 参数 2（帧间隔） | N | 每隔 N 帧激光雷达数据建一次图，1 即每帧都建 |

帧间隔参数很实用：想图密、实时性高就设 1；数据量大、算力紧张就调大，图会稀疏一些，但建图速度更快。

### 2.2 RViz 可视化

新开一个终端：

```bash
cd /opt/carla_ws
rosrun rviz rviz -d carla_sim_config.rviz
```

### 2.3 开自动驾驶，自动建图

开启 ego_vehicle 的自动驾驶模式，车自己在场景里跑，地图自动累积。全程不用人操作，跑完看 RViz 里的建图效果。

## 3 三种地图模式对比

| 模式 | 参数 | 地图内容 | 适合场景 |
| --- | --- | --- | --- |
| 纯激光 | 0 | 只有点云几何 | 看结构、测距离 |
| 激光 + 语义分割 | 1 | 点云 + 完整语义标签 | 感知研究：车辆、行人、建筑都标出来了 |
| 激光 + 道路要素 | 2 | 只保留道路、地面、灯杆 | 高精地图雏形：去掉动态物体，只留静态道路要素 |

模式 2 最有意思 —— 车、行人这些动态目标被过滤掉，剩下的就是一条 "干干净净" 的道路结构，这是制作高精地图的常见思路。

0 - 纯激光地图 1 - 激光 + 语义分割 2 - 激光 + 道路要素

## 4 几个要点

- 语义来自前视相机：点云通过投影到相机图像拿到语义标签，所以相机视野内的点云语义最丰富
- 坐标统一靠 GPS：每帧点云转换到 GPS 坐标系，多帧累积才不会 "飘"
- C++ 实现：建图是数据密集任务，跑起来比 Python 版流畅
- 自动驾驶模式自动建图：不用手动控制车辆，跑一遍场景，点云地图就建好了。
