# Carla仿真系列：14_点云障碍物检测——不认脸，也能认出“障碍物“

第13期把地面从点云里剥掉了，这期顺势而为：剩下的非地面点云，到底有哪些障碍物？ 这是自动驾驶感知的底线能力——可以不知道"是什么"，但必须知道"有没有"。

## 1 障碍物检测：四种技术路线

| 路线 | 核心思路 | 代表算法 | 要不要训练 | 能不能识别类别 |
| ---- | ---- | ---- | ---- | ---- |
| 点云聚类 | 空间距离/密度分组，一簇=一个障碍物 | 欧氏聚类、DBSCAN、网格聚类 | 不需要 | 不能 |
| 点云检测 | 网络学习几何特征，直接输出3D框+类别 | PointNet++、VoxelNet、SECOND、PointPillars、CenterPoint | 需要大量3D标注 | 能 |
| 图像+点云 | 图像给语义，点云给距离，融合互补 | BEVFormer、TransFusion、后融合匹配 | 需要 | 能 |
| 图像+点云 | 图像做目标检测得到2D框，再利用点云和图像的投影，从点云中提取障碍物，剩下的点云再做聚类 | 目标检测，投影，聚类 | 不需要 | 能 |

四条路线各有取舍，没有绝对优劣，只有场景适配：

- 聚类：零成本、万物皆检、算力低，但"只认障碍物，不认类别"
- 点云检测：几何优先、夜间不受影响、输出精准3D框+类别，但吃标注、远距离稀点云效果差
- 图像+点云：语义+几何互补、小目标更有优势，但强依赖相机-雷达标定，标定一漂性能就崩
- 图像+点云：目标检测+投影+聚类，但依赖相机-雷达标定，不会漏检，因为有点云聚类兜底

## 2 本期落地：点云聚类方法
这期代码用的是最轻量的聚类路线，完整流程：

点云预处理（滤波降采样）
    ↓
地面分割（第13期的成果直接复用）
    ↓
聚类分割障碍物簇（空间距离/密度）
    ↓
计算 3D 包围盒（多边形）输出

工程取舍：不识别类别（车/人/石头都当"障碍物"），换来的是无需训练、无需标注、嵌入式都能跑。

## 3 启动流程

前几步和系列一致（5个终端）：

```bash
# 终端1：启动容器
cd carla_sim && bash dev_start.sh
# 终端2：进入镜像
bash dev_into.sh
# 终端3：启动 Carla UE4
cd /opt/carla_ws && bash ./CarlaUe4.sh
# 终端4：启动 ROS Bridge
cd carla_sim && bash ros_bridge.sh
# 终端5：创建 NPC（车辆+行人）
python scripts/spawn_random_npc_py2.py _vehicle_count:=20 _walker_count:=10
```

spawn_random_npc_py2.py 支持自定义数量：车辆 20、行人 10，场景里即有静态障碍物也有动态目标。

## 5 四种方法的工程取舍对照

| 维度 | 聚类（本期） | 点云检测 | 图像 + 点云 | 图像 + 点云 |
| --- | --- | --- | --- | --- |
| 落地成本 | 最低 | 高（数据 + 训练） | 高（标定 + 算力） | 中（图像训练 + 推理 + 聚类） |
| 未知物体 | 检出 | 可能漏检 | 可能漏检 | 检出 |
| 夜间 | 稳定 | 稳定 | 依赖点云兜底 | 稳定 |
| 实时性 | 好 | 中 | 差（计算量大） | 中 |
| 适合场景 | 简单机器人、嵌入式 | 自动驾驶感知 | 复杂城区 | 低速场景 |

## 6 几个要点

- 聚类是 "底线感知"：不要求身份识别，先保证 "有障碍物" 不漏报
- 地面分割是前置条件：不去地面直接聚类，地面会连成一大片，啥都分不出来（这就是第 13 期的意义）
- 参数敏感：聚类阈值对远距离稀疏点云、物体粘连场景要调，过分割 / 欠分割是常态
