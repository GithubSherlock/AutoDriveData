# Carla仿真系列：16_多激光雷达标定——让三个雷达的“眼睛“对齐

之前在社群里有小伙伴让我讲下多激光雷达的标定，这一期就简单讲下给车装三个激光雷达，做环视点云。但装上去只是第一步——三个雷达的外参不准，点云就会各说各话，后面感知也无法做。这期就讲：误差怎么来的，标定怎么做。

## 1 先说结论：多雷达的核心是"对齐"

三个雷达 = 三双眼睛
外参（位置+朝向）不准 → 三双眼睛看到的世界错位 → 融合点云糊成一团
标定 = 求解每个雷达相对车体（或相互之间）的旋转 R 和平移 t

## 2 添加三个激光雷达

改`objects.json`，加三个`sensor.lidar.ray_cast`：

| 传感器 | 安装位置 (x, y, z) | 作用 |
| ---- | ---- | ---- |
| front_lidar | (2.39, 0.0, 0.68) | 车头前方 |
| leftback_lidar | (-2.39, 0.92, 0.8) | 左后角 |
| rightback_lidar | (-2.39, -0.92, 0.8) | 右后角 |

三个雷达参数一致（32线、50米量程、20Hz、上下FOV 2°/-26.8°），构成围绕车身的环视点云。

启动 ROS Bridge 后，就能在 RViz 里看到三个雷达的点云同时出现。

## 3 模拟安装误差

真实世界里，雷达装上车的角度和位置一定有误差——安装工人不可能装得绝对精准，仿真环境里面不存在安装误差。 所以我们故意引入误差来复现问题：

```bash
cd sim_workspace/multisensor_calib
python lidar_transform_py2.py
```

脚本通过订阅每个雷达的点云，施加人为的平移 + 旋转误差后重新发布：

| 雷达 | 平移误差 (m) | 旋转误差 (度) |
| --- | --- | --- |
| front_lidar | [0, 0, 0] | [0, 3, 0] |
| leftback_lidar | [0.2, 0, 0] | [0, 0, 3] |
| rightback_lidar | [0, 0.1, 0] | [2, 0, 0] |

3 度看起来很小，但 50 米远处就是 2.6 米的偏差 —— 这就是标定要解决的问题。

## 4 标定方法

### 方法一：人工标定靶标

用棋盘格、角反射器、特制标定板、球形标靶，步骤：

1. 在所有雷达的共同视野内放靶标
2. 每个雷达各自提取靶标特征（球心 / 角点 / 平面），得到该特征在各雷达坐标系下的坐标
3. 得到多组 "同一物理特征在不同雷达下的 3D 坐标对"
4. 用 ICP / PnP / SVD 分解 求解 R、t，最小化特征点间距离误差
5. 多次移动靶标、采集多帧，优化降噪

优点：精度高、稳定；缺点：要搭场地、人工摆靶标。

### 方法二：无靶标自动标定（环境特征法）

利用自然环境特征：墙面、墙角、地面平面、建筑边缘。

核心思想：同一个真实物体，在两个雷达点云里的几何结构应该对齐。

1. 两帧点云各自提取几何特征（平面、边缘）
2. 目标函数：最小化两个雷达对应平面 / 边缘之间的距离
3. 迭代优化 R、t，直到 B 的几何结构和 A 重合

经典算法：NDT（正态分布变换）、ICP、平面配准
优点：不用靶标、可在线自动标定；缺点：依赖环境。

关键约束

| 约束 | 说明 |
| --- | --- |
| 公共视场是前提 | 两个雷达没有重叠视野，就无法标定 |
| 单帧解不出 6 自由度 | 需要多姿态 / 多位置采集，充分激励所有自由度 |
| ICP 初值很重要 | 容易局部最优；先用粗略估计（手工测量 / CAD 图纸）给初值，再精调 |

## 5 标定工具

参考开源项目 SensorsCalibration，这里提供一个简单的手动标定工具：

```bash
cd sim_workspace/multisensor_calib
python server.py
```

功能：

- 图像可视化
- 按话题显示每个传感器的点云
- 手动调整每个传感器的外参
- 合并所有传感器外参，输出最终标定结果

这是手动标定的简单工具；实际工程里根据场景和精度要求，选择合适的自动化方案（靶标标定 / 无靶标优化）。

## 6 这期的心得

- 标定是感知的基础
  外参错一点，后面融合、检测、建图全跑偏。
- 三度误差放大到 2.6 米
  这就是为什么标定要用高精度靶标，而不是 "差不多就行"。
- 初值决定成败
  无论是 ICP 还是优化，给它一个好起点，比调参数更重要。
