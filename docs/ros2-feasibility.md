# ROS2 引入可行性评估(2026-09-28)

> **本文档的定位**:回答「**要不要**把这套 ROS2 引入 AutoDriveData」。**不改任何代码**,只出判据与触发条件。
> 前置:[docs/ros2-humble-build.md](ros2-humble-build.md) 已证明它**可得**(155 包 / 跨进程 pub-sub 通 / 端到端验收过)。
> **可得 ≠ 该用** —— 本文回答后半句。
>
> **与 Plan.md §5.12 无关**:那条 2026-09-14 终止的是**官方 MapTR/MapQR 代码复线**,不是 ROS2。
> 本文不复活任何已终止的线,也不改变 Plan.md / Plan2.md 里任何已有结论。
>
> **判据来源**:项目自身的成文约束(§1)+ 四组成对实测(docs/ros2-humble-build.md)+ 工业惯例对照(§4,标注置信度)。

## 0 结论

**不引入。** 三条判据,按硬度排序:

| # | 判据 | 事实 |
|---|---|---|
| **1** | **疼点已被绕过** | ROS2 唯一能解决、而项目真疼的问题,是 `live_studio` 的 **GIL 饿死 worker**(同一对点云 ICP 在 worker 线程 eff **0.04–0.24**,主线程同步 **0.90–1.00**)。当前口径「**在线 SLAM 默认同步执行**」已经把它解决到 **0.90–1.00**(Plan2 §P-L)。**问题没了,方案的价值跟着没了** |
| **2** | **能力线已经 16 次选择不用它** | 教程 11–16 的能力(SLAM / 单双目 / 多雷达 / 语义建图 / 3DGS / 轨迹)**全部以纯 python 降档打通,每条各有判据**。ROS2 提供的是**中间件**,不是**能力**;中间件不产生新结论 |
| **3** | **代价可量化,收益不可量化** | 见 §3。代价是"环境互斥 + 守卫要加维度 + 复现链翻倍",收益目前全部落在"更好看/更顺手"侧 |

**保留一条窄接口**(§5):若将来出现**外部消费方**,首选 `rosbag2` 作**导出目标**(加法),而非把内部管线迁上去。
**现在不做**,因为它现在是**没有消费方的导出**。

## 1 评估口径:先定"值得"的判据

不先定判据,讨论会退化成偏好之争。本项目有**三条已成文**的硬约束,任何引入都必须先回答它们:

| 约束 | 出处 | 对引入的含义 |
|---|---|---|
| **① 分层守卫**(四档 `_PURE` / `_CARLA_OK` / `_TORCH_OK` / `_ANY`,最长前缀匹配) | `autodrivedata/tests/test_layer_guard.py` 的 `LAYER_RULES` | 新依赖必须被**声明进某一层**;落不进现有四档就得加档 |
| **② 依赖单向**:AutoDriveData → AutoLabel(3D 检测消费方),**禁止反向** | CLAUDE.md「分层纪律」 | ROS2 若成为公共底座,会造出**第二条**跨项目腿 |
| **③ 环境**:主线全在 conda `autodrivedata`(**python 3.11.16**);ROS2 只能用**系统 python 3.10.12** | 实测,ros2-humble-build.md §4.1 | 二者**互斥**,不是叠加 |

**判据的判据**:一项引入算"值得",必须至少满足一条 ——
(a) 解决一个**当前存在**的疼点;(b) 产生一个**新的、可量的**结论;(c) 打开一个**否则做不到**的能力。
"更顺手""更标准""生态更全"**都不算**。

## 2 ROS2 能提供什么,逐项对照本项目

| ROS2 能力 | 项目现状(已有判据) | 净收益 |
|---|---|---|
| 多进程节点 + DDS 通信 | `live_studio` 单进程 8 路;**GIL 问题已用同步执行绕过**(eff 0.90–1.00) | **低**(疼点已解) |
| `tf2` 坐标变换 | `calib/core.py` + rig 表 + `slam/eval_slam` 的 **M·T·M 手性共轭 + 杆臂修正**,带回归钉 | **低**(已有,且有坑记忆钉住) |
| 时间同步 / `message_filters` | CARLA **同源仿真**,天然同步;A/B 帧级配对是硬门槛且有纪律 | **0** |
| 传感器驱动生态 | 项目是 **CARLA 仿真** —— 驱动生态是**真车**才需要的东西 | **0** |
| 分布式多机 | 单机 | **0** |
| `launch` 编排 | 命令清单 + **runlog 三件套**(18 入口)+ `live_studio` 的 CLI | **低** |
| rviz2 / foxglove 可视化 | `sim/view_stream` + `sim/live_studio` + `map/viz_maptr_pred` + `utils/fonts` 的 overlay 体系 | **中**(属"更好看",按 §1 判据**不算"值得"**) |
| `rosbag2` 记录 / 回放 | KITTI root + **逐帧契约**(`map/mapvec_schema.py`)+ 自带时间戳关联 | **中**(仅"对外交换"时兑现,见 §5) |
| 生态复用(`slam_toolbox` / LIO-SAM / nav2) | 自研纯 numpy 降档已通;教程口径是**「能力闭环」不是「精度对标」** | **中-高名义,实测低** —— 见 §5 |
| **能力本身**(感知 / 建图 / 定位) | 三条线全部自研且各有判据;`perception/` 被守卫强制**不 import carla** | **0** |

**读法**:收益不为 0 的三项(可视化 / bag / 生态复用)**全部落在"对外"或"排场"侧**,没有一项落在项目自己的结论链上。

## 3 代价(可量化部分)

| 代价 | 量化 |
|---|---|
| **环境互斥** | ROS2 = 系统 python 3.10.12;主线 = conda 3.11.16。`.bashrc:124` **无条件** `conda activate autodrivedata` ⇒ 同一个 shell 不能同时是两者;`ros2env.sh` 干的正是把 conda 踢掉 |
| ★ **分层守卫会静默失效** | `_PURE = frozenset({"carla","torch"}) \| _MASQ` —— **`rclpy` 不在任何禁用集合里**。引入 ROS2 后,`utils/` 里 `import rclpy` **不会报错**。必须在 `LAYER_RULES` 加**第五个维度**,否则"谁 import 了 ROS"无人管 |
| **构建 / 复现** | 源码 155 包、首次 **7 min 48 s + 1 min 7 s**(8 worker)+ 一次踩坑(已留档);官方 humble **apt 装不了**(需 22.04 源与 root) |
| **测试面翻倍** | 54 个测试文件 / **1071 用例基线**全跑在 conda python;ROS2 侧要另建一套同规格的守卫与用例 |
| **新的胶水层** | ROS2 消息 ↔ numpy / 项目结构 需要转换层 —— **而现有胶水已经够用**(KITTI root + 逐帧契约 + AutoLabel 消费它) |
| **偏离数据惯例** | rosbag2 是**记录**格式;主流 AV 数据集**没有一个是 rosbag**(见 §4) |

## 4 工业惯例对照

> ⚠️ 本节是**惯例性对照**(公开事实级),**未做正式检索/引用**。若要当决策级引用,需另补来源。
> 按本项目「选型先问工业界惯例」的口径给出,目的是**不让"工业界都这么干"这种半句陈述过关**。

| 层 | 惯例 | 对本项目的含义 |
|---|---|---|
| **研发 / 原型** | ROS2 广泛使用;**Autoware 是 ROS2 原生**;传感器接入、可视化、回放大量用 ROS | 若本项目要接**真实车**,ROS2 是默认选择 —— **但项目现在是仿真,这条不成立** |
| **量产 / 车端** | 大量**去 ROS 化**:实时性与确定性、安全认证(ROS2 核心不做认证)、依赖体积 ⇒ 自研中间件或直接 DDS。Waymo / Cruise / Tesla 的自研栈不基于 ROS | "工业界都在用 ROS2"是**不完整的陈述**;准确说法是**研发期常用、量产期常去** |
| **数据集 / 数据管道** | nuScenes(json + `.pcd.bin` + jpg)、Waymo(tfrecord/parquet)、Argoverse(parquet)、KITTI(txt + png/bin)—— **主流 AV 数据集都不是 rosbag**;rosbag 更多出现在机器人/科研的**采集现场** | 项目的 **KITTI root 路线与业界数据集惯例一致**;把 rosbag2 当**内部**格式是**偏离**惯例,当**导出**目标才顺 |

**映射回本项目**:三层惯例里,只有「研发/原型」层支持引入,而**它支持的前提(真实传感器接入)本项目不满足**。
其余两层要么不承诺,要么明确**反向**。

## 5 若要用:唯一有判据的候选,以及它为什么现在也不该做

| # | 用途 | 判据 | 为什么现在不做 |
|---|---|---|---|
| **1** | **拿官方 ROS2 版 FAST-LIO2 / LIO-SAM 做「对标基线」**,给自研 numpy 降档一个独立第三方参考点 | 同一条 `outputs/kitti_loop` 上比 **ATE** | ★ **CARLA 不漂移**(项目已实测,Plan2 §P-H.3):两条实现的 ATE 都会很小 ⇒ **对比的区分度低**。要让它有区分度,得先有**漂移更明显的真实/退化数据** |
| 2 | `rosbag2` 作**导出**目标(加法,不动内部架构) | 前提 = **有外部消费方** | **前提不成立**:现在唯一消费方 AutoLabel 吃 KITTI root + 逐帧契约 |
| 3 | rviz2 / foxglove 看数据 | 无判据(自研 overlay 已体系化) | 按 §1 判据 **"更好看"不算值得** |
| 4 | 把 `sim/` / `perception/` / `slam/` 迁到 ROS2 | 无判据,且违反 §1 全部三条约束 | **不做** |

**#1 与项目既有方法论是同一路子**(项目做过 HiVT 复现、MapTR 自实现 —— 「自研 vs 原版」对照是这个项目的习惯)。
**但它是"可做",不是"该做"** —— 它不改变任何现有结论,而区分度受限于仿真数据本身不漂移。

## 6 触发条件:什么情况下回来重评

**下面任一条成立,本文结论作废,重评:**

| # | 触发 | 为什么它会翻转结论 | 重评时先做什么 |
|---|---|---|---|
| 1 | **接真实车 / 真实传感器** | 驱动生态 + 时间同步从 **0 变刚需**;「研发/原型层」的惯例前提才成立 | 先算驱动侧的最小可用集,别先迁管线 |
| 2 | **出现外部消费方**(要给别人用数据 / 模型) | §5 的 #2 前提成立,rosbag2 导出才兑现价值 | 先确认消费方要什么格式(nuScenes 风格通常比 bag 更受欢迎) |
| 3 | **`live_studio` 再撞并发/实时性瓶颈**(同步执行撑不住) | `0.90–1.00` 的 eff 是**当前口径**的结果,不是物理上限 | 先用 `time.thread_time()/wall` 量出新 eff,再判断是否真需要多进程 |
| 4 | **有了漂移明显的真实/退化数据** | §5 #1 的对标基线才有区分度 | 先在这个数据上量自研 ATE,再决定要不要引外部基线 |
| 5 | 需要一个**独立第三方**来完成某项能力(自研成本明显超预算) | §1 判据 (c) 成立 | 单点评估,别整体引入 |

**注意**不是触发条件的两件事:① 「ROS2 很标准 / 生态全」—— 那是偏好,不是判据;② Plan.md §5.12 的官方栈复线 —— 与 ROS2 无关,别混。
